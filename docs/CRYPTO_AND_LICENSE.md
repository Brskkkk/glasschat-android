# E2EE integration boundary and license

GlassChat now declares the official Android artifact `org.signal:libsignal-android:0.106.2` in `:core-crypto`, from Signal's Maven repository (`https://build-artifacts.signal.org/libraries/maven`). The owner explicitly selected Signal libsignal. The library is licensed under AGPL-3.0-only; review the license and distribution obligations before distributing either APK. Signal's project says third-party use is unsupported and its APIs may change, so upgrades need deliberate compatibility review.

`SignalSessionCrypto` is only a thin adapter around the official `SessionBuilder` and `SessionCipher`. The constructor signatures were checked against the tagged v0.106.2 source: `SessionBuilder(SignalProtocolStore, SignalProtocolAddress remote, SignalProtocolAddress local)` and `SessionCipher(SignalProtocolStore, SignalProtocolAddress local, SignalProtocolAddress remote)`. The adapter accepts a caller-supplied `SignalProtocolStore` and a `PreKeyBundle` that its caller is responsible for authenticating and verifying; it delegates session establishment, encryption, and decryption to libsignal. Its envelope preserves Signal's PREKEY/WHISPER type and opaque serialized bytes. It rejects unrelated message types, and provides no custom-crypto or plaintext relay fallback. See [SessionBuilder.java](https://github.com/signalapp/libsignal/blob/v0.106.2/java/shared/java/org/signal/libsignal/protocol/SessionBuilder.java) and [SessionCipher.java](https://github.com/signalapp/libsignal/blob/v0.106.2/java/shared/java/org/signal/libsignal/protocol/SessionCipher.java).

`SealedSignalProtocolStore` now implements libsignal's identity, pre-key, signed-pre-key, session, sender-key and Kyber-pre-key store interfaces. It persists protocol records through `SealedLocalStore`, whose AES-GCM payload encryption uses a non-exportable Android Keystore key; the Signal key/session bytes and identifying keys are within encrypted payloads, while SQLite retains the record kind and opaque digest row id. It creates and persists a local Signal identity pair and registration ID on first access, and supports storing one-time as well as explicitly designated last-resort Kyber keys. For a last-resort Kyber key it preserves the `(Kyber key, signed pre-key, base key)` reuse history across key removal/rotation and rejects a repeated tuple. This store and the `:core-crypto` → `:core-data` dependency are source-only and have not been compiled or tested.

`SignalMessagePipeline` is wired through the Owner and Client screens and authenticated Supabase relay coordinator. It requires an existing pinned Signal session, writes only bounded Signal ciphertext to the local outbox, and has no plaintext fallback. Inbound transport mappings are authenticated and matched to verified peer devices; messages are decrypted and stored only in encrypted local records before the coordinator acknowledges relay copies. Ratchet advancement and local message/outbox writes share SQLite transactions. Duplicate inbound delivery IDs are idempotent and do not count as newly stored messages. This is source-only; no build or interoperability validation has run.

Both apps schedule WorkManager retries and inbox polling after peer verification. Users can separately opt in to generic local notifications when polling discovers newly stored messages. Those alerts contain no sender or message text and are not FCM/push; Android may delay polling. FCM setup, token lifecycle, push delivery and notification reliability remain future work. The periodic sync now stages a new signed EC and last-resort Kyber key pair after 30 days, using sealed monotonic IDs and a retryable publication-pending manifest. It retains old private key records for in-flight bundles; safe retirement/cleanup and on-device/interoperability validation remain incomplete. Backup/recovery is also incomplete. Supabase migrations are source only, with no connected/deployed project or live authenticated service.
No build or tests were run; the owner explicitly deferred those until all requested implementation is in place. Dependency resolution and compilation remain unverified in this repository; checking the constructor declarations is not a build or test.
